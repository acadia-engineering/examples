# Examples

These simple examples show how to use Elm and Acadia together.


## Running the Examples

Download this repository:

```bash
git clone https://github.com/acadia-engineering/examples.git
cd examples
```

Move to the example you want to experiment with:

```bash
cd 01-foods
```

And then compile the Acadia and Elm code.

```bash
acadia make --gen-elm=gen
elm make src/Main.elm
acadia serve --html=index.html
```

This compiles the Acadia endpoints to Elm code in `gen/`, then compiles the Elm code to `index.html`, and then serves your database and frontend at [`http://localhost:9000`](http://localhost:9000).

I like to run them as a one-liner so that I never forget a step:

```bash
acadia make --gen-elm=gen && elm make src/Main.elm && acadia serve --html=index.html
```


## SQLite Files

If you want the data to persist, you can publish the database like this:

```bash
acadia plan
# This will create v1.0.0.plan that you should look at.
# I did not write error messages for any of the stuff here, so if you run into
# a problem, just delete v1.0.0.plan and generate it again from scratch.

acadia sign
# This will create v1.0.0.signed which is a binary file.
# This is like "approving" the plan. It is more useful when there are more
# complex migrations.

acadia publish v1.0.0.signed foods.sqlite
# This will create foods.sqlite
```

From there you can work with the `foods.sqlite` file:

```bash
acadia make foods.sqlite --gen-elm=gen
elm make src/Main.elm
acadia serve foods.sqlite --html=index.html
```

Working with endpoints generated by `acadia make foods.sqlite` becomes crucial once you publish your first MINOR or MAJOR change. Endpoints have stable IDs across migrations, so anything that adds or removes endpoints must be hooked into the history to get the correct IDs.
